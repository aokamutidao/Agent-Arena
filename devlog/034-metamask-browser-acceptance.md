## 前端账户提示与登录恢复修复（最终 runtime-v4）

修复实际复现的换账户后旧 Agent 保存提示残留：账户、链、会话及退出切换清空提示与草稿，旧账户的迟到成功/失败响应不能覆盖新账户的保存状态。新增四项相关测试，第一次修复共 **34/34 通过**，生产构建通过。新实现的跨账户提示清理目前仅有自动化回归，未另行重复“保存 Agent 后切账户”的浏览器操作；相关测试验证实际组件的 Hook 生命周期与迟到响应隔离，不称为完整 DOM 或浏览器集成测试。

随后在切换独立前端产物并刷新时实际发现：钱包会自动恢复，但登录会话丢失。源码确认 wagmi 的 SSR 存储恢复与重连尚未完成时，初始 `disconnected` 被 AuthProvider 误当作真正断开，提前删除了持久会话。修复通过 WagmiProvider 的公开 `initialState` 将启动状态设为 `reconnecting`，待连接收敛后才恢复与当前钱包、链匹配的会话；真正断连、换账户、换链与退出仍清会话。上下文立即隐藏不匹配的旧 token，迟到 profile 成功/401 与登录响应受请求代次、身份和当前 token 校验保护，不能覆盖或清除新会话。

新增八项登录恢复回归，使用实际 auth 组件与内存存储，并调用已安装的 `@wagmi/core` 验证初始化和重连完成状态。最终全量前端测试 **42/42 通过**，`npm run typecheck`、auth/钱包 Provider 文件 lint 与生产构建均通过；构建包含全量 lint、类型检查和 15 页生成。仅保留既有 WalletConnect 可选 `pino-pretty` 警告。最终构建显式使用 API `http://localhost:18081`、RPC `http://127.0.0.1:18545`。

`frontend-runtime-v3` 曾用于端口 3002；最终由 root 仅切换前端到独立 `frontend-runtime-v4`，保留 API、原链和数据库，不重置此前赛事。现场 reload 时，旧 v3 的有效主办方会话在 v4 中从初始连接提示自动恢复为 Organizer、Sign out 与 `0x70…79C8`，没有新登录签名。截图暂存 `.local/llm-demo/metamask-v4-reload-auth-preserved.jpg`。这项登录恢复有实际浏览器复验，不新增资金交易或模型调用。

早期提示修复日志保留 `.local/llm-demo/034-frontend-tests.txt`、`034-frontend-build.txt`；最终测试与构建日志为 `034-auth-tests.txt`、`034-frontend-v4-build.txt`，独立产物运行说明为 `frontend-runtime-v4.README.md`，均位于 `.local/llm-demo/`。
