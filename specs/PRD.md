# S1 - 产品需求文档 (PRD)

## Agent Arena：AI Agent 格子竞技场

---

## 1. 产品定位

**一句话描述**：两个 AI Agent 在格子上对战，观众下注并投票决定 AI 策略方向。

**核心叙事**：
> 这不是 AI 帮你干活。这是 AI 替你打架。你不仅是观众，还是教练——你押的钱决定 AI 怎么打。

**竞品差异**：

| | 传统预测平台 (Polymarket) | AI 工具 (ChatGPT) | Agent Arena |
|--|--|--|--|
| 用户角色 | 被动下注 | 被动接受 AI 输出 | 主动参与：下注 + 指挥 |
| AI 角色 | 辅助分析 | 服务用户 | 对抗参与者 |
| 观赏性 | 无 | 无 | 实时对战 + 策略博弈 |
| 区块链必要性 | 结算 | 无 | 下注托管 + 策略投票 + 结果验证 |

---

## 2. 用户角色

### 2.1 观众-赌徒 (Viewer-Bettor)

**画像**：进入平台看 AI 对战，想通过下注赚钱。

**核心诉求**：
- 看懂谁在打、谁占优势
- 快速下注，操作简单
- 知道赢了能拿多少钱

**用户故事**：
```
作为一个观众，
我想在两个 AI Agent 对战时下注，
这样我能通过判断胜负赚钱。
```

### 2.2 策略教练 (Strategy Coach)

**画像**：不满足于被动下注，想影响 AI 的决策。

**核心诉求**：
- 下注时能选择 AI 的策略方向
- 知道自己的投票权重有多大
- 看到自己投票的策略是否生效

**用户故事**：
```
作为一个策略教练，
我想在下注时投票决定 AI 的打法（激进/稳健/诡道），
这样我能影响战局，增加赢面。
```

### 2.3 Agent 创建者 (Agent Creator)

**画像**：开发者，创建新的 AI Agent 并部署到平台。

**核心诉求**：
- 定义 Agent 的性格、技能、外观
- Agent 获胜能带来声誉（链上胜率记录）
- （未来）Agent 能赚钱

**MVP 阶段不开放此角色**，平台预置 4 个 Agent。

## 3. 核心用户流程

### 3.1 完整流程（从进入平台到结算）

```
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 1：进入平台                                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1.1 用户连接钱包（MetaMask）                                    │
│  1.2 查看当前/即将开始的对局列表                                  │
│  1.3 选择一场对局进入观战页面                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 2：下注 + 策略投票（对局开始前 & 进行中）                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  2.1 查看两个 Agent 的信息（名字、性格、历史胜率）                 │
│  2.2 选择押哪一方（Red / Blue）                                  │
│  2.3 输入下注金额（USDC）                                        │
│  2.4 同时选择策略投票：                                          │
│      - 🔥 激进（冲脸猛打）                                       │
│      - 🛡️ 稳健（防守反击）                                       │
│      - 🎲 诡道（蓄力 + 偷袭）                                    │
│  2.5 确认交易 → USDC 锁定到合约，策略投票记录上链                  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 3：观战（对局进行中）                                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  3.1 观看格子地图上的实时对战（每回合 5 秒）                      │
│  3.2 查看双方 HP、状态、当前回合数                               │
│  3.3 查看实时赔率变化（基于双方下注池比例）                       │
│  3.4 查看策略投票分布（多少人选激进/稳健/诡道）                   │
│  3.5 对局进行中仍可追加下注（赔率动态调整）                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│ 阶段 4：结算（对局结束后）                                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  4.1 胜负判定 → 结果提交到合约                                   │
│  4.2 合约自动计算赢家份额（扣除 5% 协议费）                       │
│  4.3 赢家点击"提取" → USDC 回到钱包                              │
│  4.4 Agent 胜率记录更新上链                                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 策略教练机制详解

```
下注时的策略投票：

用户 A：押 5 USDC 在 Red，选"激进"
用户 B：押 10 USDC 在 Red，选"稳健"
用户 C：押 8 USDC 在 Blue，选"诡道"

→ Red 方的策略分布：
  激进：5 USDC (33%)
  稳健：10 USDC (67%)
  → Red Agent 的实际行为 = 33% 激进 + 67% 稳健

→ Blue 方的策略分布：
  诡道：8 USDC (100%)
  → Blue Agent 的实际行为 = 100% 诡道

投票权重 = 下注金额 / 该方总下注金额
```

## 4. MVP 功能范围

### 4.1 MVP 做什么

| 模块 | 功能 | 优先级 |
|------|------|--------|
| 游戏引擎 | 10x10 格子、移动/攻击/技能/蓄力、回合制、胜负判定 | P0 |
| AI Agent | 4 种预设性格（Berserker/Tactician/Trickster/Defender）、基于策略投票的决策 | P0 |
| 智能合约 | 下注池、策略投票记录、自动结算、Agent 胜率记录 | P0 |
| 后端 | 游戏状态管理、WebSocket 实时推送、合约交互 | P0 |
| 前端 | 观战界面（格子地图 + HP 条）、下注面板、策略投票、结算提取 | P0 |
| 钱包 | MetaMask 连接、Sepolia 测试网 | P0 |

### 4.2 MVP 不做什么（明确排除）

| 功能 | 排除原因 |
|------|---------|
| Agent 创建者功能 | 复杂度高，MVP 用预设 Agent |
| 道具投喂（Item Shop） | 可作为 v2 功能 |
| 弹幕系统 | 可作为 v2 功能 |
| 多语言支持 | 先做英文版 |
| Agent 间组合/谱系 | v2 功能 |
| 移动端适配 | 先做桌面端 |

## 5. 数据模型（核心实体）

### 5.1 Game（对局）

```
Game {
    id: uint256              // 对局 ID
    agentRed: Agent          // 红方 Agent
    agentBlue: Agent         // 蓝方 Agent
    status: GameStatus       // Pending | Betting | Playing | Finished
    startTimestamp: uint256  // 开始时间
    endTimestamp: uint256    // 结束时间
    winner: Side             // None | Red | Blue
    totalBetRed: uint256     // Red 方总下注（USDC）
    totalBetBlue: uint256    // Blue 方总下注（USDC）
    currentRound: uint8      // 当前回合
    maxRounds: uint8         // 最大回合数（30）
}
```

### 5.2 Agent（AI Agent）

```
Agent {
    id: uint256              // Agent ID
    name: string             // 名字
    personality: Personality // 性格类型
    wins: uint256            // 胜场
    losses: uint256          // 负场
    hp: uint8                // 当前 HP（对局中）
    position: Position       // 当前位置（x, y）
}
```

### 5.3 Bet（下注记录）

```
Bet {
    gameId: uint256          // 对局 ID
    user: address            // 用户地址
    side: Side               // Red | Blue
    amount: uint256          // 下注金额
    strategyVote: Strategy   // Aggressive | Defensive | Tricky
    claimed: bool            // 是否已提取奖金
}
```

### 5.4 Position（格子坐标）

```
Position {
    x: uint8                 // 0-9
    y: uint8                 // 0-9
}
```

## 6. 状态机

### 6.1 对局状态流转

```
    ┌──────────┐
    │ Pending  │ 对局已创建，等待开始
    └────┬─────┘
         │ 开始下注
         ↓
    ┌──────────┐
    │ Betting  │ 下注开放（对局开始前 2 分钟）
    └────┬─────┘
         │ 下注截止 / 时间到
         ↓
    ┌──────────┐
    │ Playing  │ 对战进行中（每回合 5 秒）
    └────┬─────┘
         │ 一方 HP = 0 或达到最大回合数
         ↓
    ┌──────────┐
    │ Finished │ 对局结束，等待结算
    └──────────┘
```

### 6.2 回合状态（Playing 阶段）

```
    ┌──────────────────────┐
    │ TurnStart            │ 回合开始
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │ AgentRedDecide       │ Red Agent 做决策（基于策略投票）
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │ AgentBlueDecide      │ Blue Agent 做决策
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │ ResolveActions       │ 解析动作（移动、攻击、伤害计算）
    └──────────┬───────────┘
               ↓
    ┌──────────────────────┐
    │ CheckWinCondition    │ 检查胜负
    │                      │ - 一方 HP = 0 → Finished
    │                      │ - 回合数 = 30 → 比较 HP
    │                      │ - 否则 → 下一回合
    └──────────────────────┘
```

## 7. 非功能性需求

### 7.1 性能

| 指标 | 要求 |
|------|------|
| 回合推送延迟 | < 500ms（后端 → 前端） |
| 合约结算 Gas | < 200k Gas / 场 |
| 并发观战人数 | 支持 100 人同时观战一场 |
| AI 决策时间 | < 2 秒 / 回合（Qwen API 调用） |

### 7.2 安全

| 风险 | 应对措施 |
|------|---------|
| 合约被攻击 | 使用 OpenZeppelin 库，限制重入 |
| AI 决策被篡改 | 每步动作 hash 上链，事后可验证 |
| 下注被抢跑 | 下注截止后锁定，不再接受新下注 |
| 结算不公 | 合约自动结算，无需人工干预 |

### 7.3 可验证性

```
每场对局链上记录：
- 两个 Agent 的 ID
- 每步动作的 hash
- 最终结果
- 策略投票分布

→ 任何人可以验证：AI 没有作弊，结果没有被篡改
```
