# 第一次体验：从看回放到亲自结算一场赛事

适用版本：课程版 Agent Arena。核查日期：2026-10-10（Asia/Singapore）。

本指南供你亲自操作，先浏览，再体验退款，最后创建并完成一场新赛事。全部使用本机 Anvil 测试链和 DUSD 测试代币，无需充值、购买 ETH 或配置模型 API Key。当前对战模式为 `deterministic_simulation`，页面明确显示“确定性模拟（非 LLM）”。

本次只读核查确认服务、角色和余额正常；没有替你发送交易，也没有将下面的操作说明当成已经完成的 MetaMask 全流程验收。[核查记录](evidence/experience-preflight-2026-10-10.json)。

### 2.3 添加本地网络

在 MetaMask 网络选择器里添加自定义网络，填写：

| 字段 | 填写内容 |
| --- | --- |
| 网络名称 | `Agent Arena Local`（仅是显示名称） |
| RPC URL | `http://127.0.0.1:18545` |
| Chain ID | `31337` |
| 货币符号 | `ETH` |
| 区块浏览器 URL | 留空 |

如果已有 Chain ID 31337 的网络，核对并选择 RPC 为 18545 的配置；不要只按旧网络名称判断。保存后切换到这个网络。[官方添加网络说明](https://support.metamask.io/networks-and-sidechains/managing-networks/how-to-add-a-custom-network-rpc/)。

### 2.4 连接和登录是两步

1. 用 Chrome 打开 <http://localhost:3001/tournaments>。
2. 点击顶部“Connect Wallet”，选择 MetaMask，在扩展中选择当前要使用的演示账户并连接。
3. 确认网页顶部地址与这个账户一致、网络为本地链。
4. 点击网页“签名登录”，核对消息内的 `localhost:3001`、Chain ID 31337 和 Manager 与当前环境一致，再在 MetaMask 签名。
5. 主办方应显示 `organizer`，审核员应显示 `auditor`。普通参赛/赞助钱包没有这两个管理角色是正常的。

**每次换账户：MetaMask 切换 → 核对网页地址 → 再点“签名登录”。** 若网页地址没有跟随变化，在钱包中检查此网站连接的账户，或在网页断开后重连。不要只改账户昵称。

登录是身份签名，不会转账或花费 gas；后面创建赛事、报名、赞助等操作才是链上交易。

### 2.5 记住所有交易的共同操作

每次看到“估算……”按钮，都按这个顺序：

**点击估算 → 在本页交易状态卡核对操作和 gas → 点击“钱包签名发送” → 在 MetaMask 确认 → 等待“交易确认成功”。**

只点“估算”不会提交交易！交易状态卡可能位于页面靠下，需要滚动查找。成功后等页面刷新，通常约 10 秒；修改输入值后必须重新估算。链时间与截止时间显示在赛事详情页，不要只看电脑时钟。

## 3. 先完成一个最短操作：给过期赛事退款

这是理解“按钮 → 钱包 → 链上状态 → 资金流水”最快的一段，当前只需要赞助方账户。

1. 切到**赞助方**，连接并登录，打开 [#3 赛事](http://localhost:3001/tournaments/3)。
2. 核对“我的赞助”为 **200 DUSD**，最终结算期限已经过去。
3. 点击“估算到期取消”，按共同交易操作完成签名。
4. 等待状态变为“已取消”。取消本身尚未退款。
5. 点击“领取 200 DUSD 退款（估算）”，再估算、发送、确认。
6. 成功后可退金额消失，钱包 DUSD 增加 200；操作前无其他变动时，赞助方余额由 700 变为 900。
7. 打开资金概览：若无其他变动，累计赞助仍为 325，已退赞助变为 225，待结算资金变为 0。

如果你此前已完成取消或退款，就从当前状态继续，或跳过这段；不能重复领取。

## 4. 准备两个参赛 Agent，再创建新赛事

先准备账户和 Agent，可以避免创建赛事后忙于初始化、错过报名时间。

1. 切到**红方参赛者**并签名登录，打开[我的 Agent](http://localhost:3001/agents)。
2. 若已有 `Aggressive Scholar`，可以直接使用；也可填写“Agent 名称”为 `我的进攻 Agent`，“策略与性格”为 `aggressive`，点击“保存 Agent 定义”。
3. 切到**蓝方参赛者**并重新签名登录，使用已有 `Patient Guardian`，或创建 `我的防守 Agent`，策略填写 `defensive`。
4. 两边都应看到自己的 Agent 卡片和内容哈希。保存定义只写后端，不会弹出链上交易确认。

当前模拟器识别 `aggressive`、`defensive` 等策略关键词；它不会像真实 LLM 一样理解任意复杂策略。定义保存后不可修改，调整策略需要创建新定义。

## 5. 亲手完成一场新赛事

### 5.1 主办方创建

切到**主办方**并登录，打开[赛事页](http://localhost:3001/tournaments)，填写：

| 字段 | 首次体验建议值 |
| --- | --- |
| 赛事名称 | `我的第一次完整体验` |
| 指定审计员钱包 | `0x3C44CdDdB6a900fa2b585dd299e03d12FA4293BC` |
| 规则链接（可选） | 留空 |
| 距报名截止（分钟） | `10`，给首次切换账户、报名和赞助留出时间 |
| 距最终结算期限（小时） | `24` |
| 结果审核窗口（秒） | `60` |

点击“模拟并估算创建费用”，再按共同交易操作发送。成功后新赛事出现在列表，记下它的编号，后面始终进入这一场；不要假定一定是 #4。

期限以**点击估算时的链时间**计算。不要估算后放置很久才发送。想缩短等待，可以在熟练之后创建更短报名窗口的下一场；已创建赛事不能修改期限。

### 5.2 赞助方放入 100 DUSD

切到**赞助方**并登录，进入新赛事详情：

1. “赞助金额（DUSD）”填写 `100`。
2. 点击“1. 估算授权”，发送并等待确认。授权对象应为本环境的奖金托管合约 `0x9f1ac54bef0dd2f6f3462ea0fa94fc62300d3a8e`。
3. 再点击“2. 估算赞助”，再次发送并等待确认。
4. 成功标志：奖金总额为 **100 DUSD**，“我的赞助”为 **100 DUSD**，赞助方余额减少 100。

授权只允许合约按规则扣币，不会增加奖池。即使已有足够授权，也可以按上述两步完整体验；不要把授权成功当成赞助成功。指定审核员不能赞助自己审核的赛事。

### 5.3 两位参赛者分别报名

先切到**红方参赛者**并登录，在新赛事“参赛与资金”里选择自己的 Agent，点击“估算报名”，发送并确认。看到报名人数 **1 / 2**。

再切到**蓝方参赛者**，重复登录、选择自己的 Agent、报名。看到 **2 / 2**。先报名的是红方，后报名的是蓝方，所以本次按上面的顺序操作。

报名免费，但报名交易消耗本地测试 ETH。主办方和指定审核员不能作为自己的赛事参赛者。

### 5.4 主办方开赛并运行

切回**主办方**并登录，等待详情页的“链时间”达到“报名截止”。满两人也仍需等截止；可以利用这段时间查看资金和报名事件。

1. 点击“估算开赛”，发送并等待成功。此时链上状态变为“对战中”。
2. 点击“运行 Agent 对战”。这是后端任务，不需要再签一笔链上交易。
3. 等待页面显示回合记录和结果。当前演示执行速度很快，可能直接出现完整回放，拖动滑块逐回合看即可。
4. 核对页面显示“确定性模拟（非 LLM）”，查看位置、HP、动作及结果。

不要把“开赛”与“运行对战”混为一步。已完成的同一场对战不能再次运行覆盖证据。

### 5.5 主办方提交结果

1. 向下找到“完整对战证据”，点击“展开证据内容”或“下载完整证据 JSON”，实际检查内容。
2. 确认“下载内容哈希与对战证据哈希一致”。
3. 回到“组织者操作”，点击“估算提交结果”，发送并确认。
4. 成功后进入结果审核状态，页面显示提名冠军、审核截止时间，证据区提示“链上提交哈希也一致”。

**必须先查看或下载证据，提交按钮才会启用。** 提交冠军地址和证据不会自动付款。

以这场实际显示的结果为准，不预设红方或蓝方必胜。如果是平局，当前规则没有冠军、不能提交胜者；应等待最终结算期限后取消退款。这个限制也是当前平台的一部分。

### 5.6 审核员确认

切到**审核员**并登录，进入同一场赛事，查看回放并再次展开或下载完整证据。

等待链时间到达“审核截止”（本场从提交结果开始计算 60 秒），点击“估算审核通过”，发送并确认。

成功标志：赛事状态为“已结算”，显示冠军地址和“等待冠军钱包领取奖金”。审核员须是创建时指定的那位；其他有 auditor 角色的钱包不能替代。

### 5.7 冠军领奖

核对本场冠军地址，切到对应的**红方或蓝方参赛者**，连接并登录：

1. 点击“领取 100 DUSD 奖金（估算）”，按共同交易操作发送。
2. 成功后看到“奖金已领取”，领取按钮消失，赢家钱包余额增加 100 DUSD。
3. 蓝方已有此前的奖金，因此应比较**增量**，而不是要求每个赢家最终余额都等于 100。
4. 在[审计流水](http://localhost:3001/audit)选择新赛事，核对 `TournamentFunded`、`ParticipantRegistered`、`TournamentStarted`、`ResultSubmitted`、`ResultApproved` 和 `PrizeClaimed`。

如果此前只完成本文的 #3 退款和本场 100 DUSD 赛事，没有其他操作，最终资金概览应为：累计赞助 **425**、已发奖金 **200**、已退赞助 **225**、待结算 **0 DUSD**，赞助方钱包余额为 **800 DUSD**。

这时完整体验了一条：**资金预存 → 报名 → 对战 → 证据 → 独立审核 → 用户自行提款**。

## 6. 再体验取消、异议和管理员权限（可选）

### 6.1 主办方主动取消

再建一场新赛事，赞助方放入 25 DUSD。**开赛前**，主办方在“异议、裁决或取消说明”填写“本次为取消退款体验”，点击“保存理由并估算取消”，发送交易。无需先凑齐两位参赛者。

状态变“已取消”后，换赞助方领取 25 DUSD 退款。取消说明先保存在后端，只有取消交易确认后才正式改变链上状态。

### 6.2 结果异议和裁决

这条路径需要另一场完整对战。创建时建议把审核窗口设为 **300 秒**，留出切账户和填写说明的时间。依照正常流程完成结果提交后：

1. 在审核截止之前，换成该场参赛者或实际赞助者，登录并填写测试异议说明，例如“演练：请求审核员复核回放中的结果”。
2. 点击“保存说明并估算异议”，发送交易。确认状态变为“存在异议”；仅保存草稿不等于已经提出链上异议。
3. 换回指定审核员，登录、查看证据及说明，等待原审核窗口结束。
4. 在“异议裁决结果”选择冠军，或选择“否决结果，取消赛事并退款”，填写理由，点击“保存裁决并估算提交”，发送交易。
5. 选择冠军则由冠军领奖；选择取消则由各赞助者领取自己的退款。

不要在第一场正常体验中途插入异议，否则就进入裁决分支，无法再点普通的审核通过按钮。

### 6.3 退出报名与管理员角色

- 报名截止之前，已报名参赛者可点“估算退出报名”，完成交易后名额恢复；之后可重新报名。
- 导入管理员账户并登录，在赛事页可看到“管理员角色管理”，选择组织者或审计员，填写目标钱包，估算授权或撤权。首次主流程的角色已经配好，无需调整；如要练习，使用另一个专门测试钱包，避免撤销正在体验中的主办方/审核员角色。

| “估算开赛”报错 | 奖池非零、两人报名、已到报名截止、未到最终结算期限；旧 #3 已过期 |

| 取消后没有到账 | 还要换赞助钱包领取退款；取消不会自动转账 |

| 页面的事件或余额稍晚更新 | 等约 10 秒刷新；核对资金页索引区块是否追上链头 |
| “链时间：读取中…”长时间不变 | 检查 RPC 可达、三个服务仍在运行、页面和钱包配置使用同一节点 |

## 8. 服务停止后如何重新体验

当前演示是临时环境：重启脚本会创建新的链和数据库，原手工赛事不会保留。想长期保留数据，按 [运行与部署](DEPLOYMENT.md) 的“日常持久化开发”处理。

先确认当前服务已停止，再从两个终端启动；端口占用说明可能已有服务，不要盲目杀进程或重复启动。

终端 A（前提：依赖、合约产物和 Go 二进制已构建）：

```bash
cd /Users/mac/Desktop/hackathon/agent-arena
COURSE_SMOKE_RPC_PORT=18545 COURSE_SMOKE_API_PORT=18080 COURSE_SMOKE_UI_PORT=3001 node tooling/smoke-course.mjs --serve
```

终端 B：

```bash
cd /Users/mac/Desktop/hackathon/agent-arena/frontend
NEXT_PUBLIC_API_URL=http://localhost:18080 NEXT_PUBLIC_LOCAL_RPC_URL=http://127.0.0.1:18545 npm run dev -- --port 3001
```

两个终端保持运行，打开 <http://localhost:3001>。不带 `--serve` 的 smoke 是一次性自动测试，通过后会退出并清理，不能用它来持续浏览。`./start.sh` 也不会自动替你启动 Anvil 和部署合约。

新临时环境重新核对配置、余额和赛事期限，旧文档里的 #3“已过期”只适用于本次核查快照。重新建链后 MetaMask 若仍记录旧待处理交易，先检查这些交易是否属于旧环境，再按钱包帮助处理本地活动记录。
