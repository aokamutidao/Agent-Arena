顶部工具栏提供 **English / 中文** 切换，选择会在本浏览器保存。下面教程使用中文按钮名，英文导航对应关系见[用户手册](USER_GUIDE.md#中英文切换)。切换语言不会翻译已有赛事名称或原始证据。

适用版本：课程版 Agent Arena。核查日期：2026-10-10（Asia/Singapore）。

本指南供你亲自操作，先浏览真实比赛与已完成退款，再创建并完成一场新赛事。全部使用本机 Anvil 测试链和 DUSD 测试代币，无需充值、购买 ETH；参赛者无需个人模型 API Key，平台已配置真实 LLM。当前真实示例是 #5（`qwen3.5-plus`），历史 #1 仍是 `deterministic_simulation`，回放与证据会区分实际模式。

### 2.3 添加本地网络

在 MetaMask 网络选择器里添加自定义网络，填写：

| 字段 | 填写内容 |
| --- | --- |
| 网络名称 | `Agent Arena Local`（仅是显示名称） |
| RPC URL | `http://127.0.0.1:18545` |

| 货币符号 | `ETH` |
| 区块浏览器 URL | 留空 |

如果已有 Chain ID 31337 的网络，核对并选择 RPC 为 18545 的配置；不要只按旧网络名称判断。保存后切换到这个网络。[官方添加网络说明](https://support.metamask.io/networks-and-sidechains/managing-networks/how-to-add-a-custom-network-rpc/)。

### 2.4 连接和登录是两步

1. 用 Chrome 打开 <http://localhost:3002/tournaments>。
2. 点击顶部“连接钱包”，在中文钱包弹窗中选择 MetaMask，再在扩展中选择当前要使用的演示账户并连接。
3. 确认网页顶部地址与这个账户一致、网络为本地链。
4. 点击网页“签名登录”，核对消息内的 `localhost:3002`、Chain ID 31337 和 Manager 与当前环境一致，再在 MetaMask 签名。
5. 主办方应显示“主办方”，审核员应显示“审核员”，管理员显示“管理员”。普通参赛/赞助钱包顶部显示“普通用户”：这表示没有全局管理角色，不表示已经报名。详情页“你的下一步”和“我的赛事账户”会另行标出本场参赛者、赞助者等身份。

**每次换账户：MetaMask 切换 → 核对网页地址 → 再点“签名登录”。** 若网页地址没有跟随变化，在钱包中检查此网站连接的账户，或在网页断开后重连。不要只改账户昵称。

登录是身份签名，不会转账或花费 gas；后面创建赛事、报名、赞助等操作才是链上交易。

### 2.5 记住所有交易的共同操作

所有链上业务按钮都按这个顺序操作：

**点击具体业务按钮 → 自动弹出交易确认窗口，先检查和估算 → 核对操作、金额和预估网络费 → 点击“确认并在钱包签名” → 在 MetaMask 确认 → 等待“交易已确认成功”，点击“完成”。**

例如“确认报名，查看费用”“开始比赛”“领取 100 DUSD 奖金”，第一次点击都只是准备交易，不会自动发送；无需再滚动寻找页面底部的确认卡。弹窗内 ETH 是网络费，与操作中的 DUSD 金额分开核对。修改表单后必须重新点击业务按钮并估算。

可以按 Escape 或“收起窗口”关闭弹窗。关闭不等于取消已发送的交易；页面右下方（手机底部）会保留“查看交易进度”或“查看并检查回执”，可重新打开。等待签名、链上确认或最终状态未明时，不要重复提交；状态未明时点击“检查链上回执”。

成功后等待数据刷新，通常约 10 秒。详情页“奖金与规则”可查看报名、审核和最终期限，以及“当前链时间”；不要只看电脑时钟。上方网络状态可展开“网络详情”，查看合约和同步进度。

## 4. 准备两个参赛 Agent，再创建新赛事

先准备账户和 Agent，可以避免创建赛事后忙于初始化、错过报名时间。

1. 切到**红方参赛者**并签名登录，打开[我的 Agent](http://localhost:3002/agents)。
2. 若已有 `Aggressive Scholar`，可以直接使用；也可在“创建参赛 Agent”选择“进攻型”，填写“Agent 名称”为 `我的进攻 Agent`，核对“策略与性格”为 `aggressive`，点击“保存 Agent，准备参赛”。
3. 切到**蓝方参赛者**并重新签名登录，使用已有 `Patient Guardian`，或选择“防守型”，创建 `我的防守 Agent`，策略填写 `defensive`。
4. 两边都应在“已保存的 Agent”看到自己的卡片；“查看定义指纹”展开内容哈希，“带它去参赛”进入赛事页。保存定义只写后端，不会弹出链上交易确认。

当前 3002 环境的新比赛由真实 LLM 读取 Agent 策略；也可以复用本钱包已有的 `Local LLM Red` / `Local LLM Blue` 定义。历史模拟器只识别 `aggressive`、`defensive` 等关键词，不代表真实模型表现。定义保存后不可修改，调整策略需要创建新定义。

## 5. 亲手完成一场新赛事

### 5.1 主办方创建

切到**主办方**并登录，打开[奖金赛事](http://localhost:3002/tournaments)，点击“创建赛事”展开表单，填写：

| 字段 | 首次体验建议值 |
| --- | --- |
| 赛事名称 | `我的第一次完整体验` |
| 指定审核员钱包 | `0x3C44CdDdB6a900fa2b585dd299e03d12FA4293BC` |
| 规则链接（可选） | 留空 |
| 距报名截止（分钟） | `15`（新表单默认值），给首次切换账户、报名和赞助留出时间 |
| 距最终结算期限（小时） | `24` |
| 结果审核窗口（秒） | `60` |

点击“预览并创建赛事”，在自动弹窗核对操作、指定审核员和报名截止，再按共同交易操作发送。成功后新赛事出现在列表，记下它的编号，后面始终进入这一场；不要假定一定是 #4。“收起创建表单”只收起输入区域，不代表撤销已发送的创建交易。

期限以**点击“预览并创建赛事”时的链时间**计算。不要预览后放置很久才发送。想缩短等待，可以在熟练之后创建更短报名窗口的下一场；已创建赛事不能修改期限。

### 5.2 赞助方放入 100 DUSD

切到**赞助方**并登录，进入新赛事详情：

1. 在“参与这场赛事”选择“赞助奖金”，将“赞助金额（DUSD）”填写为 `100`，也可点 `100 DUSD` 快选按钮。
2. 点击“1. 授权 100 DUSD”，在自动弹窗核对并签名，等待确认。授权对象应为本环境的奖金托管合约 `0x9f1ac54bef0dd2f6f3462ea0fa94fc62300d3a8e`。
3. 页面显示金额已授权后，再点击“2. 确认赞助”，在新弹窗核对 **100 DUSD** 并再次签名确认。
4. 成功标志：“本场奖金总额”为 **100 DUSD**，“我的赞助 · 仍在托管”为 **100 DUSD**，赞助方余额减少 100。

授权只允许合约按规则扣币，不会增加奖池。即使已有足够授权，也可以按上述两步完整体验；不要把授权成功当成赞助成功。指定审核员不能赞助自己审核的赛事。

### 5.3 两位参赛者分别报名

先切到**红方参赛者**并登录，在新赛事“参与这场赛事”选择“报名参赛”，选择自己的 Agent，点击“确认报名，查看费用”，按弹窗操作发送并确认。看到报名人数 **1 / 2**。

再切到**蓝方参赛者**，重复登录、选择自己的 Agent、报名。看到 **2 / 2**。先报名的是红方，后报名的是蓝方，所以本次按上面的顺序操作。

报名免费，但报名交易消耗本地测试 ETH。主办方和指定审核员不能作为自己的赛事参赛者。

### 5.4 主办方开赛并运行

切回**主办方**并登录，等待详情页的“链时间”达到“报名截止”。满两人也仍需等截止；可以利用这段时间查看资金和报名事件。

1. 在“你的下一步”点击“开始比赛”，发送并等待成功。此时链上状态变为“对战中”。
2. 点击“运行 Agent 对战”。这是后端任务，不需要再签一笔链上交易。
3. 等待页面自动更新回合记录和模型调用，耗时取决于模型；仅配置了 LLM 不等于调用成功。若请求或解析失败，比赛会中断，先查看错误；仅在后台允许恢复时再点“恢复对战执行”。
4. 核对本场显示真实 LLM 模式与成功调用记录；完成后逐回合查看双方动作、位置、HP 和实际结果。可播放、暂停、切换上一/下一回合或拖动滑块。若显示确定性模拟，不得将其记为真实 LLM 验收。

不要把“开赛”与“运行对战”混为一步。已完成的同一场对战不能再次运行覆盖证据。

### 5.5 主办方提交结果

1. 点击“你的下一步”中的“查看比赛证据”，或找到“比赛证据”，点击“展开完整证据”或“下载证据 JSON”，实际检查内容。
2. 核对“内容校验通过”；已查看后会显示“已查看”。“证据指纹与核验说明”可展开完整哈希。
3. 回到“你的下一步”，点击“提交比赛结果”，在弹窗确认并签名。
4. 成功后进入“审核窗口中”，页面显示提名冠军、审核截止时间；证据区应显示“内容与链上记录一致”。

**必须先查看或下载证据，提交按钮才会启用。** 提交冠军地址和证据不会自动付款。

以这场实际显示的结果为准，不预设红方或蓝方必胜。如果是平局，当前规则没有冠军、不能提交胜者；应等待最终结算期限后取消退款。这个限制也是当前平台的一部分。

### 5.6 审核员确认

切到**审核员**并登录，进入同一场赛事，查看回放并再次展开或下载完整证据。

等待链时间到达审核截止（本场从提交结果开始计算 60 秒），在“你的下一步”点击“审核通过，确认冠军”，发送并确认。

成功标志：赛事状态为“已结算 · 待领奖”，显示冠军地址和等待领取提示。审核员须是创建时指定的那位；其他拥有“审核员”管理角色的钱包不能替代。

### 5.7 冠军领奖

核对本场冠军地址，切到对应的**红方或蓝方参赛者**，连接并登录：

1. 在“你的下一步”点击“领取 100 DUSD 奖金”，按共同交易操作发送。
2. 成功后状态显示“已领奖”，页面提示奖金已领取，领取按钮消失，赢家钱包余额增加 100 DUSD。
3. 蓝方已有此前的奖金，因此应比较**增量**，而不是要求每个赢家最终余额都等于 100。
4. 在[审计流水](http://localhost:3002/audit)选择新赛事，核对 `TournamentFunded`、`ParticipantRegistered`、`TournamentStarted`、`ResultSubmitted`、`ResultApproved` 和 `PrizeClaimed`。

如果以 033 后快照为起点，仅完成本节这场 100 DUSD 赛事且没有其他操作，资金概览应为：累计赞助 **550**、已发奖金 **300**、已退赞助 **250**、待结算 **0 DUSD**，赞助方钱包余额为 **700 DUSD**。实际验收仍比较本场余额增量与回执，不预设赢家。

这时完整体验了一条：**资金预存 → 报名 → 对战 → 证据 → 独立审核 → 用户自行提款**。

## 6. 再体验取消、异议和管理员权限（可选）

### 6.1 主办方主动取消

再建一场新赛事，赞助方放入 25 DUSD。**开赛前**，主办方展开“需要取消这场赛事？”，在“取消原因”填写“本次为取消退款体验”，点击“取消赛事，查看费用”，按弹窗操作发送交易。无需先凑齐两位参赛者。

状态变“已取消”后，换赞助方领取 25 DUSD 退款。取消说明先保存在后端，只有取消交易确认后才正式改变链上状态。

### 6.2 结果异议和裁决

这条路径需要另一场完整对战。创建时建议把审核窗口设为 **300 秒**，留出切账户和填写说明的时间。依照正常流程完成结果提交后：

1. 在审核截止之前，换成该场参赛者或实际赞助者，登录并填写测试异议说明，例如“演练：请求审核员复核回放中的结果”。
2. 展开“对结果有异议？提交复核申请”，填写“异议依据”，点击“提交异议，查看费用”，按弹窗操作发送交易。确认状态变为“存在异议”；仅保存说明草稿不等于已经提出链上异议。
3. 换回指定审核员，登录、查看证据及说明，等待原审核窗口结束。若准备判定冠军，必须查看并核验一致的证据；若原证据缺失或不可靠，可选择否决并取消退款，仍需填写理由并等待窗口结束。
4. 点击“查看异议并裁决”，在“审核异议并裁决”中选择“裁决结果”：冠军，或“否决结果，取消赛事并退款”。填写“裁决理由”，点击“提交裁决，查看费用”，按弹窗操作发送交易。
5. 选择冠军则由冠军领奖；选择取消则由各赞助者领取自己的退款。

不要在第一场正常体验中途插入异议，否则就进入裁决分支，无法再点普通的审核通过按钮。

### 6.3 退出报名与管理员角色

- 报名截止之前，已报名参赛者可在“参与这场赛事”点“退出本场报名”，按弹窗操作完成交易后名额恢复；之后可重新报名。
- 导入管理员账户并登录，在奖金赛事页展开“管理员：管理主办方与审核员权限”，选择“主办方”或“审核员”，填写目标钱包，点击“预览授予权限”或“预览撤销权限”，再按弹窗操作签名。首次主流程的角色已经配好，无需调整；如要练习，使用另一个专门测试钱包，避免撤销正在体验中的主办方/审核员角色。

## 7. 卡住时按症状检查

| 症状 | 优先检查 |
| --- | --- |
| 点 MetaMask 后出现二维码 | 改用本机 Chrome + MetaMask 扩展；本机链不走手机扫码路径 |
| 钱包显示 0 ETH，或网络看似正确却交易失败 | 核对演示地址与 RPC **18545**；Chain ID 相同也可能连到旧 8545 节点 |
| 连接了钱包却没有创建赛事按钮 | 选择主办方 `0x7099…79C8`，再“签名登录”；新建个人钱包没有主办方权限 |
| 换了钱包，网页仍显示之前的地址 | 检查网站连接的账户；必要时断开重连，并重新签名登录 |
| 我的 Agent 为空 | 定义属于钱包；确认当前登录地址，或创建一份自己的定义 |
| 钱包里看不到 DUSD | MetaMask 未必自动展示自定义代币；先看详情“我的赛事账户”里的“钱包可用余额”。可按下面的合约地址手动导入代币 |
| 点业务按钮后赛事/余额没变 | 还要在自动弹窗点“确认并在钱包签名”，并在 MetaMask 确认；点击业务按钮只准备交易 |
| 授权成功但奖池仍为 0 | 还需点击“2. 确认赞助”，并签名发送赞助交易 |
| 已经两个人，开赛按钮仍不可点 | 等链时间达到报名截止；同时检查主办方身份和登录 |
| “开始比赛”不可点或报错 | 奖池非零、两人报名、链时间已到报名截止，且仍能留出完整审核窗口；旧 #3 已取消，需创建新赛事 |
| 运行完却不能提交结果 | 先展开/下载证据，确认哈希一致且不是平局；账户须为主办方 |
| 审核按钮灰色 | 须指定审核员、已查看证据、哈希一致、原审核窗口结束，且最终期限未过 |
| 赛事已结算但没有到账 | 还要换冠军钱包自行领奖；审核不会自动转账 |
| 取消后没有到账 | 还要换赞助钱包领取退款；取消不会自动转账 |
| 提示 nonce、登录过期或 401 | 重新“签名登录”；如果是钱包交易 nonce，先核对网络与待处理交易，不要重复发送 |
| “交易状态需要核查” | 点“检查链上回执”，不要马上重新发送；收起弹窗后从底部进度入口重新打开 |
| 页面的事件或余额稍晚更新 | 等约 10 秒刷新；核对资金页索引区块是否追上链头 |
| “当前链时间”持续读取中 | 检查 RPC 可达、三个服务仍在运行、页面和钱包配置使用同一节点 |

当前 DUSD 合约：`0x5FbDB2315678afecb367f032d93F642f64180aa3`，符号 `DUSD`，精度 `6`。该地址只描述本次部署；重新部署后应以 <http://localhost:18081/api/config> 为准。

## 8. 服务停止后如何继续当前环境

当前 API 18081 使用 `.local/llm-demo/course.db`，与旧 API 共用已有 18545 链。先检查端口和进程，不要盲目杀进程或重复启动。

若只是新 API / 前端停止，按 [本地真实模型指南](LOCAL_LLM_DEMO.md) 与 [运行与部署](DEPLOYMENT.md) 恢复原配置、数据库和 3002 / 18081 服务，核对 `/ready`、部署地址和原赛事。`./start.sh` 不会自动启动 Anvil 或部署合约。

**不要把 `smoke-course.mjs --serve` 当成当前环境的恢复命令。** 它创建新的测试链和临时数据库，不能接续 #5 / #6 的记录。Anvil 停止或链状态丢失时，先保留资料并按备份与恢复流程人工核对；数据库里的 hash 无法恢复全部链状态，备份恢复演练仍未验收。

## 9. 体验完成后你应该能解释的事情

- 连接钱包、签名登录和发送交易分别做什么。
- 为什么赞助有授权和入金两步，审核通过后还要冠军自己领取。
- 主办方、审核员、参赛者和赞助方各自能做哪些操作。
- 回放与原始证据保存在哪里，链上哈希能核对什么。
- 到期、主动取消和争议否决如何走到退款。
- #1 的历史模拟与 #5 的真实 LLM 记录有什么区别；033 CLI 已通过哪些检查，034 MetaMask、公开部署和外部评价仍有哪些待验收项。
